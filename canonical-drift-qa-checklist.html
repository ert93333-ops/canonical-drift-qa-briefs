Checklist focus

Canonical QA is signal alignment.

Review final URLs, canonical tags, sitemap rows, and redirects together before the release goes live.

1. Capture page and canonical pairs

  1. Export the final page URL and the rendered canonical URL for each launch template.
  2. Check that expected self-canonicals are actually self-referencing.
  3. Document every intentional non-self canonical.
  4. Remove staging, preview, QA, dev, and localhost canonicals from production rows.

2. Compare protocol, host, path, and slash rules

  1. Confirm final URLs and canonical targets use HTTPS.
  2. Check apex vs www behavior and cross-domain canonicals.
  3. Confirm trailing slash rules match redirect behavior.
  4. Review query-parameter pages and faceted URLs separately from clean canonical targets.

3. Compare sitemap and canonical rows

  1. Confirm launch URLs that should be indexed are present in the sitemap.
  2. Confirm canonical targets are present when they are meant to be indexable.
  3. Remove staging or HTTP URLs from sitemap rows.
  4. Retest after CMS, ecommerce, or static build sitemap generation changes.

4. Check redirects and final destinations

  1. Capture final destination URLs after redirect rules are active.
  2. Check migration redirect maps against canonical targets.
  3. Avoid canonical tags pointing to URLs that immediately redirect elsewhere.
  4. Retest after CDN, host, slash, or lowercase-normalization rules change.

5. Keep the guarantee honest

  1. Canonicals are signals, not absolute commands.
  2. Search engines may select a different canonical if signals conflict.
  3. Use this checklist as launch QA, then monitor real indexing data after release.
